# Command-Based Assignment 2025

Each student will submit their own FRC Command-Based Robot project on their own Git branch. Read carefully—missing files or incorrect setup will prevent the simulator from running.

---

## Project Overview
You will:
- Create a command-based robot project with WPILib 2025.
- Push the complete project to your own branch in this repository.
- Verify the project builds and runs in the WPILib simulator.

---

## How This Repo Works (Branches)

Every student must use their own branch. Do not push to `main` or anyone else’s branch.

### 1) Clone
```
git clone <REPO_URL>
cd Command-Based-Assignment-2025
````

### 2) Create/Switch to your branch

```
# first time
git checkout -b <your-branch-name>

# later
git checkout <your-branch-name>
```

### 3) Add your robot project (full project, not just src/)

Include all required files/folders (see “Required Files” below), commit, and push:

```
git add .
git commit -m "Add my command-based robot project"
git push --set-upstream origin <your-branch-name>   # first push
# afterwards:
git push
```

---

## Required Files (must be present)

Your project must include, at minimum:

* `build.gradle`
* `settings.gradle`
* `gradlew`, `gradlew.bat`
* `gradle/` (wrapper directory)
* `src/` (all robot code; Java path typically `src/main/java/frc/robot/...`)
* `src/main/deploy/` (if used)
* `vendordeps/` (any vendor JSONs you use)
* `.wpilib/` (generated by WPILib project)
* If you created the project without desktop support, see the next section and then re-generate or update your `build.gradle`.

If any of these are missing, the simulator will not run.

---

## Enable Desktop Simulation Support (one-time per project)

WPILib’s Desktop Simulator requires “Desktop Support”:

**Option A: VS Code**

* Open Command Palette: `WPILib: Change Desktop Support Enabled Setting`
* Set **Enable Desktop Support** to **true**.

**Option B: Manually in `build.gradle`**

* Ensure `includeDesktopSupport = true`.

Note: Some vendor libraries do not support desktop sim. If a vendor library crashes in sim, guard its usage with `if (RobotBase.isReal()) { ... }`.

---

## Running the Simulator (WPILib 2025)

### Recommended: VS Code

1. Open Command Palette → **WPILib: Simulate Robot Code**
2. When prompted, choose **Sim GUI**.
3. The Simulation GUI will launch. Do **not** use the generic “Run” button in VS Code; it does not set up sim correctly.

### Command line (Java)

From the project root:

```bash
./gradlew simulateJava
```

### Build without sim (sanity check)

```bash
./gradlew build
```

## Common Issues and Fixes

* **Wrong JDK (IntelliJ or terminal)**
  Use the WPILib-bundled JDK (typically at `C:\Users\Public\wpilib\2025\jdk` on Windows). Non-WPILib JDKs (e.g., Corretto on Windows) can break simulation. In IntelliJ, set the Project SDK to the WPILib JDK. On the command line, ensure the WPILib JDK is first in `PATH`.

* **macOS sim crashes after updating WPILib**
  Run a clean build:

  ```bash
  ./gradlew clean
  ```

  Then re-run simulation.

* **VS Code “Run” button doesn’t work for sim**
  Always use **WPILib: Simulate Robot Code** from the Command Palette, not the generic run button.

* **Vendor libraries crash in sim**
  Not all vendors support desktop sim. Wrap vendor-specific device creation or usage in `if (RobotBase.isReal()) { ... }`.

## Recommended Project Structure

```
your-project/
├── build.gradle
├── settings.gradle
├── gradle/
├── gradlew
├── gradlew.bat
├── vendordeps/
├── .wpilib/
└── src/
    └── main/
        ├── java/
        │   └── frc/robot/
        │       ├── Robot.java
        │       ├── RobotContainer.java
        │       ├── commands/
        │       ├── subsystems/
        │       └── Constants.java
        └── deploy/
```
